# Risk ranking, opportunity history, and watch retainers

**Date:** 4 September 2026

Protocol **1.6.5**. Agents get a required `risk` block and risk-then-APY ranking, a bounded APY/TVL history series with a stability signal, and walletless watch retainers. Execution-shape golden fixtures cover the remaining protocols. Canix still never holds keys or submits transactions.

## What shipped

### Required `risk` on every public opportunity (checklist 13.7)

Every public opportunity row now includes a designed `risk` object. `confidence` is always present (from snapshot age). Adapters map real fields only: CompX utilization / LTV / liquidation threshold / borrow APR / reward runway, Folks utilization / borrow APR, Tinyman `is_stable` → volatility bucket and IL hint. When an address is in context (personalized, plans, eligibility), lending rows may include wallet health factor.

`GET /opportunities`, search, protocol lists, personalized, and `POST /plans` rank by those constraints **before** raw APY. `rankOpportunitiesByApy` is a deprecated alias with the new semantics. Strict clients that parsed the old row shape without `risk` must accept `risk.confidence`. Agents that took `data[0]` as highest APY will see a different top row.

Contract: `docs/normalized-opportunity-schema.md` **1.4.0**. MCP tool copy matches (“ranked by risk then APY”).

### Opportunity history and APY stability (checklist 13.11)

Paid `GET /opportunities/:opportunityId/history?window=1d|7d|30d` (default 30d) returns `{ points, stability }`. Empty series until hourly Redis snapshots exist — not a warehouse backfill. Stability (coefficient of variation of APY) merges onto `risk` and can warn plans (`snapshot-apy-unstable`). Ranking treats unknown/medium as a mild penalty and low stability as stronger.

Research SKU **0.01 USDC**, session-eligible. MCP: `canix_get_opportunity_history`. Expect empty points and `stability: unknown` for the first ~3 hours after deploy.

### Watch / webhook retainers (checklist 13.9)

Paid `POST /watch` and `POST /watch/refresh` (0.25 USDC, one-shot only) register an Algorand **address** plus thresholds (health factor, claimable USD, APY drop, Réti capacity) and an optional HTTPS webhook. Canix stores no wallet keys. Crossings deliver HMAC-signed JSON (`X-Canix-Signature`, `X-Canix-Idempotency-Key`). `GET /watch/:watchId` is free. Secret rotation is `POST /watch/:id/rotate-secret` with `X-Canix-Watch-Secret`.

MCP: `canix_create_watch`, `canix_refresh_watch`, `canix_get_watch`, `canix_rotate_watch_secret`. Policy `canix://watch`; receipt `canix://watch/{watchId}`. Production without Redis fail-closes. See `protocol/docs/watch-retainers.md`.

### Golden fixtures (§8)

Deterministic mock-SDK group assertions for remaining execution shapes: Myth Finance, Haystack, Réti, Alpha Arcade, plus leftover Tinyman farm commit and addLiquidityAndFarm. CI compares serialized groups (stringified integers, sorted keys) without committed golden JSON blobs.

## Agent loop

1. `GET /opportunities` / `canix_list_opportunities` — top rows are risk-constrained, not highest APY. Read `risk` before sizing.
2. Optional `GET /opportunities/:id/history` / `canix_get_opportunity_history` once snapshots exist. Empty `points` means “no series yet,” not “stable.”
3. Optional `POST /watch` / `canix_create_watch` instead of polling positions. Store `webhookSecret` once; verify HMAC on callbacks. Omit `webhookUrl` for MCP-only receipts.
4. `POST /plans` still returns unsigned groups. Sign only user legs. Submit locally. Canix never holds keys.
